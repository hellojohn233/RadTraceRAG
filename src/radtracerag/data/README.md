# `radtracerag.data` —— 数据适配层（下一阶段）

本目录用于**业务语料与数据集的下载、清洗、转换**，最终产出引擎可直接摄入的文件。

## 当前状态

本阶段（通用引擎底座）**不包含**任何数据适配代码。引擎只吃「文件」，不关心文件从哪来。
等医学影像应用层开工时，SLAKE 的下载与解析代码落在这里。

## 计划放什么

| 文件 | 作用 |
| --- | --- |
| `slake.py` | 下载并解压 SLAKE（`imgs.zip` / `KG.zip` / `test.json`），把非结构化题库转成可摄入的语料文件 |
| `loader.py` | 数据集统一加载入口，给评测和问答共用 |

## 约定

- **原始数据不进仓库**：SLAKE 体积大（SLAKE `imgs.zip` 约 150 MB），统一放
  仓库根的 `data/`（已在 `.gitignore` 中），本目录只放代码。
- **下载路径可覆盖**：下一阶段会约定一个数据目录环境变量（当前统一放仓库根的 `data/`），
  具体变量名和读取逻辑随适配代码一起落地，避免先立一个没人实现的约定。
- **转换产物可复现**：从原始数据到可摄入文件的转换过程必须是纯函数式的，
  同样的输入产出同样的文件，方便评测复跑。

## 与引擎的关系

引擎（`radtracerag.engine`）是**语料无关**的，不 import 本目录的任何东西。
方向是单向的：

```
data/ 原始数据集  →  本目录的适配代码  →  可摄入的文件  →  radtracerag ingest
```

引擎不知道数据从哪来；数据适配层不知道检索怎么实现。下一阶段做医学影像问答时，
再决定这里的产物具体长什么样。
