# 界面设计规范

RadTraceRAG 的界面只有一条主线：**让用户看见答案是怎么来的。**

产品承诺是「可追溯」，所以界面不能只给一个答案。每一屏都要能回答三个问题：
看到了什么、检索到了什么、这个结论靠哪几条证据撑着。

## 视觉基调：纸面

参照物不是 SaaS 控制台，是**放射科报告和学术论文**。

理由很直接：「可追溯」这件事在纸面上就是引用制度——答案带脚注号，证据按编号
列在下方，每条写明来源。深色发光的面板、卡片堆叠、等宽字标 ID 这些是
工程界面的语言，跟"一份可以核查的文档"是两回事。

因此：

- **米白纸底**，不用纯白，纯白在屏幕上太刺
- **墨色文字**，不用纯黑
- **朱砂红**做唯一强调色，用在引用编号、命中的证据、关键动作上
- **靠分割线分区，不堆卡片**。一张纸上不需要五个盒子
- **引用用上标编号**，证据按 `[1] [2]` 列出，形态和参考文献一致

## 设计原则

1. **答案优先，证据跟上。** 答案在最上；证据在下方，可核对。
   不把证据藏进「详情」里——可追溯是卖点，不是附属功能。
2. **颜色带语义，不带装饰。** 每种颜色对应一件事，见下面的色彩表。
   界面上出现一个没定义过的颜色，就是设计出错。
3. **没有证据也是结果，要显示。** 「没有检索到证据，答案没有可回溯的支撑」
   是一句必须出现在界面上的话，不能用空白代替。
4. **未被引用的证据也列出。** 检索到却没用上，本身是有信息量的结果。

## 色彩

| 语义 | 色值 | 用在哪 |
|---|---|---|
| 墨色 | `#16202E` | 正文、结构线、影像切片、顶栏底线 |
| 朱砂 | `#C0472B` | 引用编号、命中证据、强调、Slider、主按钮 |
| 藏青 | `#234A6E` | 次级强调（备用） |
| 纸白 | `#FBFAF7` | 页面底 |
| 浅灰 | `#F1EFE9` | 侧边栏、影像灯箱底 |
| 白 | `#FFFFFF` | 输入框、证据区 |
| 分隔线 | `#E2E0DA` / `#D3D8DF` | 区块之间、控件描边 |
| 正文 | `#16202E` | 主文本 |
| 次级 | `#3C4654` | 说明、描述 |
| 弱化 | `#8A94A2` | 元信息、来源、页脚 |

logo 和界面共用这套色：logo 里的朱砂点就是界面里的引用编号。

## 字体

- **标题**：衬线（Songti SC / Source Han Serif SC / Georgia）——标题要有报告的正式感
- **正文**：无衬线（Inter / PingFang SC），行高 1.75–1.85
- **不用等宽字体标 ID**。上一版把证据 ID 设成等宽，那是控制台的做法；
  证据编号用朱砂色上标就够了
- 字号：提问 19px / 答案 17px / 正文 14.5–15px / 小标题 11px（字间距 0.16em）

## 布局

```
┌──────────────────────────────────────────────────────┐
│ logo  RadTraceRAG              [A][B][C] 对照组切换   │
├──────────────────┬───────────────────────────────────┤
│                  │  问　图中主要器官的作用是什么？        │
│   影像灯箱        │  答　图中主要器官是肝脏…[1][2]       │
│                  │  ─────────────────────────────     │
│                  │  图像观察                            │
│   4  8  4.5      │  腹部轴位断层，可见右上腹…            │
│  引用 候选 耗时    │  ─────────────────────────────     │
│                  │  检索轨迹                            │
│                  │  图像理解    VLM 读取影像…   1840 ms  │
│                  │  查询构造    把实体拼成检索词…  95 ms  │
│                  │  命中        4 条证据进入上下文  12 ms  │
│                  │  ─────────────────────────────     │
│                  │  证据                              │
│                  │  1  肝是人体最大的腺体，位于右季肋区…  │
│                  │  2  胆汁由肝细胞分泌、储存在胆囊…     │
└──────────────────┴───────────────────────────────────┘
```

- 左边影像常驻，右边是叙事流：问 → 答 → 观察 → 轨迹 → 证据
- 对照组切换在顶栏右侧，三组：A 无 RAG / B 向量 RAG / C 图增强 RAG
- 窄屏（≤1250px）所有列堆叠成单列，顺序不变

## 组件

### 影像灯箱

浅灰底（`#F1EFE9`）容器，影像居中，底部一行小字：文件名在左，尺寸和来源在右。
深色底是看片软件的惯例，但这里是「摊在灯箱上的一张片子」，浅底更贴报告的语境。

### 问答

`问` 和 `答` 加粗起头，后面正文。答案里的 `[1]` 是朱砂色上标，16px 答案里是 11px。

### 图像观察

小标题 + 分割线，内容用次级色。识别到的实体不再列徽章——这一段只负责说
「看到了什么」，实体信息在检索轨迹的查询构造那一步已经出现过。

### 检索轨迹

表格式行，三列：阶段 | 说明 | 条数与耗时。行间是点线分隔。
「命中」这一步的阶段名是朱砂色，其余是墨色——和 logo 里琥珀点/朱砂点的角色一致。

### 证据

编号列表，编号朱砂色。首条上方一条 2px 墨线，像参考文献的分隔。
每条下面一行来源（`SLAKE knowledge_base · 肝脏条目`），弱化色小字。
没有证据时显示一句话，不用空白。

### 指标

一行细排，不做卡片块。数值衬线 21px，标签 11px 弱化色。

### 对照组切换

药丸形。选中态是墨底米白字，未选中是描边透明底。原生圆点隐藏——
药丸的底色已经表达了选中状态。

## 实现

| 文件 | 职责 |
|---|---|
| `src/radtracerag/ui/theme.py` | 设计 token、字体栈、全部 CSS |
| `src/radtracerag/ui/components.py` | 组件函数，只渲染不判断 |
| `src/radtracerag/ui/app.py` | 页面编排 |
| `src/radtracerag/ui/demo_data.py` | 演示数据与合成影像生成 |
| `src/radtracerag/ui/launch.py` | 启动入口 |
| `.streamlit/config.toml` | Streamlit 主题色 |

主色走 `config.toml` 而不是 CSS 覆盖：radio、slider 这些内部组件的颜色是从
这里派生的，CSS 里硬改容易漏。

### 三个 Streamlit 的坑

**HTML 块之间不能有空行。** Streamlit 用 CommonMark 渲染 HTML，遇到空行就结束
当前 HTML 块，后面全部当字面量显示。所有片段先 `strip()` 再拼接，
见 `components._join()`。

**`file://` 图片不显示。** markdown 组件不放行本地文件协议，图标和影像都要
转成 data URI，见 `components.img_uri()`。

**`:first-child` 会误伤。** 每个 markdown 片段都是自己容器的首个子元素，
写 `.rt-section:first-child { padding-top: 0 }` 会把所有分区的上间距都清掉。

### 一处 Streamlit 主题冲突

`[data-testid="stMarkdownContainer"] p { color: 墨色 }` 会把按钮里的文字也改成
墨色，墨字压在墨底上看不见——按钮里是 `<p>` 包着文字，要单独改回来。

## 启动

```bash
uv sync
uv run radtracerag-ui
```

浏览器打开 http://localhost:8501 。

真实问答链路接上之前，界面跑的是 `demo_data` 里的假数据。
接入点在 `app.py` 的 `run_question()`，把里面换成 pipeline 调用即可，界面不动。
