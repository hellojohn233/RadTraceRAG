# 界面设计规范

RadTraceRAG 的界面只有一条主线：**让用户看见答案是怎么来的。**

产品承诺是「可追溯」，所以界面不能只给一个答案。每一屏都要能回答三个问题：
看到了什么、检索到了什么、这个结论靠哪几条证据撑着。

## 设计原则

1. **答案优先，证据跟上。** 答案在最上、最显眼；证据在下面，可展开、可核对。
   不把证据藏在「详情」里——可追溯是卖点，不是附属功能。
2. **颜色带语义，不带装饰。** 每种颜色对应一件事，见下面的色彩表。
   界面上出现一个没定义过的颜色，就是设计出错。
3. **深色是功能选择。** 医学影像是灰阶的，深底上对比度和细节都更好；
   看片软件（PACS）也是这个惯例。顺带让发光的检索轨迹在视觉上更突出。
4. **演示数据要标清楚。** 合成影像和样例答案在界面上明写，
   不能让人误以为是真实病例。

## 色彩

| 语义 | 色值 | 用在哪 |
|---|---|---|
| 检索 / 轨迹 | `#38BDF8` | 轨迹节点、轨迹连线、主按钮、进度 |
| 轨迹渐变起点 | `#22D3EE` | 弧线起点、hover |
| 轨迹渐变终点 | `#8B93F8` | 弧线终点、指标强调 |
| 证据命中 | `#FBBF24` | 引用高亮、证据 ID、命中节点、已引用徽章 |
| 图像观察 | `#7FA0C0` | 观察卡标题点、十字准星 |
| 成功 / 失败 | `#34D399` / `#F87171` | 评测结果、错误提示 |
| 页面底 | `#0A0F18` | 背景 |
| 卡片面 | `#111927` | 卡片 |
| 嵌套面 | `#0E1622` | 证据卡、输入框、指标块 |
| 描边 | `#1F2C3D` / `#2A3A4F` | 卡片边框、次级描边 |
| 正文 | `#E6EDF7` | 主文本 |
| 次级文本 | `#93A7C0` | 说明、来源 |
| 弱化文本 | `#61748D` | 元信息、脚注 |

这套色和 logo 是同一套语言：logo 里被点亮的青弧是「检索路径」，
琥珀点是「命中的证据」，中心的灰蓝准星是「影像视野」。
界面里看到青色，就知道那是系统做的；看到琥珀，就知道那是检索回来的。

## 字体

- 正文：Inter，退到 `-apple-system / PingFang SC / Microsoft YaHei`
- 数字与 ID：等宽（JetBrains Mono / SF Mono / Menlo），
  证据 ID、耗时、指标值都用等宽——这些是要被核对的，不是被阅读的
- 字号：答案 19px / 观察与证据正文 14.5px / 说明 13px / 元信息 11.5px
- 卡片标题统一 12px + 字间距 0.1em + 全大写

## 布局

```
┌──────────────┬─────────────────────────────────────────┐
│              │  答案                                      │
│  影像查看器   │  指标                                      │
│              ├──────────────────────┬──────────────────┤
│              │  图像观察              │  检索轨迹          │
│              ├──────────────────────┴──────────────────┤
│              │  证据链                                │
└──────────────┴─────────────────────────────────────────┘
```

- 影像在左栏常驻——用户要能一边看片一边看结论
- 右边是叙事流：答案 → 观察 + 轨迹 → 证据
- 窄屏（≤1250px）所有列堆叠成单列，顺序不变

## 组件

### 影像查看器

深底（`#04070C`）容器，影像居中，叠一层十字准星。
准星是 logo 元素的延续，作用是提示「这是影像，不是普通图片」。
下方一行等宽小字：文件名在左，尺寸和来源在右。

### 答案卡

- 答案正文 19px，行高 1.62
- 正文里的 `[E1]` 形式的引用带下划线：被引用的用琥珀色，没被引用的用灰色
- 答案下方列所有引用到的证据 ID，做成琥珀色徽章

### 图像观察卡

灰蓝圆点标题。正文 14.5px。下方列出识别到的实体
（器官、模态、解剖位置），用弱化徽章。

### 检索轨迹

竖向时间线，渐变竖线串起各步。每步一个节点圆点：
普通步骤是青色，「命中」步骤是琥珀色——和 logo 里琥珀点的含义一致。

每步显示：阶段名（粗）、细节（次级）、等宽的条数与耗时。

### 证据卡

- 左边 3px 色条：被引用的琥珀色，没被引用的灰色（整卡压暗）
- 标题行：等宽证据 ID + 「已引用 / 未引用」徽章
- 正文 14.5px
- 底部一行来源，如 `来源：SLAKE knowledge_base · 肝脏条目`

「未引用」的证据也展示出来——检索到但没被用上，本身是有信息量的结果。

### 指标块

一行三个：引用证据数、候选事实数、总耗时。
数值 20px 粗体，标签 11.5px。

### 对照组切换

侧边栏单选，三组：A 无 RAG / B 向量 RAG / C 图增强 RAG。
选中态是青色描边 + 淡青底。

## 实现

| 文件 | 职责 |
|---|---|
| `src/radtracerag/ui/theme.py` | 设计 token、字体栈、全部 CSS |
| `src/radtracerag/ui/components.py` | 组件函数，只渲染不判断 |
| `src/radtracerag/ui/app.py` | 页面编排 |
| `src/radtracerag/ui/demo_data.py` | 演示数据与合成影像生成 |
| `src/radtracerag/ui/launch.py` | 启动入口 |
| `.streamlit/config.toml` | Streamlit 主题色 |

主色走 `config.toml` 而不是 CSS 覆盖：radio、slider 这些内部组件的颜色
是从这里派生的，CSS 里硬改容易漏。

### 两个 Streamlit 的坑

**HTML 块之间不能有空行。** Streamlit 用 CommonMark 渲染 HTML，
遇到空行就结束当前 HTML 块，后面全部当字面量显示。
所以所有 HTML 片段都先 `strip()` 再拼接，见 `components._join()`。

**`file://` 图片不显示。** markdown 组件不放行本地文件协议，
图标和影像都要转成 data URI，见 `components.img_uri()`。

## 启动

```bash
uv sync
uv run radtracerag-ui
```

浏览器打开 http://localhost:8501 。

真实问答链路接上之前，界面跑的是 `demo_data` 里的假数据。
接入点在 `app.py` 的 `run_question()`，把里面换成 pipeline 调用即可，界面不动。
