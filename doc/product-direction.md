# 产品业务方向

## 定位

**RadTraceRAG 是面向医学影像学习与研究的证据辅助问答工具。**学习者上传公开数据集中的 X 光、CT 或 MRI 图像，提出一个具体问题；系统回答并显示它从图像中观察到什么、从知识库检索到什么。项目解决的不是“自动诊断患者”，而是“图像问题的回答能否追溯到可核查的知识证据”。

这个方向适合个人开发：输入和输出明确，公开数据可下载，不需要接入医院系统或模拟完整临床流程。与已有的合同跨文档审查项目不同，RadTraceRAG 的核心输入包含医学影像，技术重点是图像信息进入检索与回答链路。

## 用户与典型任务

- **主要用户：**医学影像学习者、医学多模态模型研究者。
- **典型问题：**影像显示的器官或模态是什么？与该器官相关的某项功能、症状或疾病知识是什么？
- **预期结果：**短答案、图像观察摘要、知识证据及其来源 ID；证据不足时说明无法从当前图像和知识库确认。

一次完整交互是：`影像 + 问题 → 图像观察 → 知识检索 → 基于证据的回答 → 展示引用`。视觉题主要检验图像理解；知识题同时检验检索和回答。界面按这两类题展示结果，避免用一个总体准确率掩盖 RAG 的实际贡献。

## 首选数据：SLAKE

[SLAKE 官方页面](https://www.med-vqa.com/slake/)提供医学影像、问答、视觉标注与结构化医学知识库，覆盖多种影像模态和身体部位；[数据文件](https://huggingface.co/datasets/BoKelvin/SLAKE/tree/main)含图像压缩包、知识库压缩包及训练、验证、测试 JSON。官方说明数据曾再次清洗，实际样本数以下载版本为准。

数据用于两个不同目的：

1. **问答评测：**使用官方测试划分的图像、问题和参考答案，分别统计 `vqa` 与 `kvqa` 题型。
2. **检索评测：**只把知识库事实作为可检索语料；从知识题中选取固定样本，人工建立“问题 → 支持它的知识事实 ID”标注。

SLAKE 的问答答案可直接评测最终回答，但它没有现成的逐题检索证据标签。尤其 `triple` 字段可出现 `vhead`、`ktail` 等占位值，**不能直接视为已标注的证据三元组**。因此项目要公开标注规则、样本 ID 和评测脚本，保证检索指标可复算。

## 产品边界

- 只回答数据集范围内的影像学习问题；不输出患者诊断、处方或治疗建议。
- 首阶段只做“图像输入 + 文本/图谱知识检索”。这属于多模态输入 RAG；**不声称已实现图像库中的图像对图像检索**。
- 不把测试问题、参考答案或由它们生成的解释写入检索库，避免评测泄漏。
- 中文界面可以做展示，但首阶段以英文题目及其原始答案计算正式指标，避免翻译差异污染分数。

## 成功标准

项目完成时应能展示三组可复现结果：视觉模型直接回答、视觉模型加普通向量检索、视觉模型加 LightRAG 图与向量混合检索。每组都报告知识题答案准确率、固定标注集的证据检索指标，以及延迟和调用成本。若图检索没有带来提升，也如实记录原因和失败样例。
