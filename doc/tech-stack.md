# 技术栈与实现方案

## 技术选型

| 层 | 选型 | 用途 |
| --- | --- | --- |
| 开发语言 | Python 3.11（项目约束为 3.11–3.13） | 数据处理、服务、实验与评测统一使用 Python |
| RAG 核心 | [HKUDS/LightRAG](https://github.com/HKUDS/LightRAG) Python SDK | 知识索引、图/向量检索与检索模式对照；开始编码时锁定具体版本 |
| 视觉理解与回答 | 首选候选：[Qwen2.5-VL-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-VL-7B-Instruct)，经统一适配器调用 | 提取图像观察，并在相同模型下比较有无检索的回答 |
| 文本向量 | 首选候选：[BAAI/bge-m3](https://huggingface.co/BAAI/bge-m3) | 建立知识事实向量索引；中文展示扩展时也可沿用 |
| 重排 | 可选：[BAAI/bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3) | 对检索候选重排；先完成无重排基线再加入 |
| 演示界面 | Streamlit | 上传影像、提问、查看答案和引用证据 |
| 实验与结果 | Python CLI + JSONL/CSV | 批量运行基线、保存逐题预测和指标 |

首阶段使用 LightRAG 的本地存储即可处理 SLAKE 的小型知识库。上述模型是实施候选，不预设它们一定取得最佳效果，也不要求全部在个人电脑上运行；统一适配器可接本地模型或兼容 API。当前 Python 包与 LightRAG 版本记录在 <code>pyproject.toml</code> 和 <code>uv.lock</code>。后续实验还需记录视觉模型名、提示词版本、检索模式、top-k 和随机参数。

## 数据与查询链路

```text
SLAKE KG ──> 事实标准化 + 稳定 evidence_id ──> LightRAG 文本块 / 知识图谱
SLAKE 图像 + 问题 ──> VLM 图像观察 ──> 查询构造 ──> LightRAG 检索
                                         └──> 图像 + 检索证据 ──> 回答与引用
```

1. **知识导入：**将知识库三元组标准化为简短事实文本，并保留原始三元组、稳定 `evidence_id` 和数据来源。同一批事实同时用于向量检索与图检索，避免基线使用不同知识。
2. **视觉观察：**VLM 只提取与当前问题有关的可见信息，例如影像模态、器官或明显异常；输出结构化字段及不确定性说明。
3. **检索：**用问题与视觉观察组成查询，调用 LightRAG 的 `naive`、`mix` 等模式；记录候选证据、排序和耗时。[官方文档](https://github.com/HKUDS/LightRAG)说明 `naive` 基于文本块向量，`mix` 融合图与文本块检索。
4. **回答：**把原图、问题和检索证据交给回答模型；输出短答案及证据 ID。引用必须能回查到实际检索结果，不能由模型凭空编造。

**二次开发点：**SLAKE 知识库适配器、图像观察与检索查询构造、证据 ID 回传、逐题追踪和评测脚本。这些模块围绕 LightRAG 扩展，不重写其存储和检索核心。LightRAG 本身也已支持多模态文档处理，但本项目首阶段的影像输入仍由独立 VLM 适配器负责，以便单独测量视觉错误与检索错误。

## 评测设计

| 对照组 | 输入给回答模型的上下文 | 用途 |
| --- | --- | --- |
| A：无 RAG | 图像 + 问题 | 测量 VLM 自身能力 |
| B：向量 RAG | 图像 + 问题 + `naive` 检索事实 | 测量普通检索收益 |
| C：LightRAG | 图像 + 问题 + `mix` 检索事实 | 测量图与向量融合的增量 |

- **答案：**按官方题型分别计算归一化 Exact Match；对开放式答案另报告 token F1 或人工核查结果，不只看总体平均。
- **证据：**在人工标注的固定知识题集合上计算 Evidence Recall@k、MRR；另抽样检查引用是否真正支持答案。
- **性能：**记录 p50/p95 延迟、模型调用次数与估算费用，和准确率一起展示。
- **公平性：**A/B/C 使用同一批测试题、相同 VLM、相同回答提示词及固定温度；B/C 的知识来源相同。测试题及答案不得进入索引。

## 实施顺序

1. 固定 SLAKE 下载版本，解析官方划分和知识库，生成事实 ID。
2. 跑通无 RAG 基线，并保存逐题预测。
3. 接入 LightRAG，完成 `naive` 与 `mix` 对照。
4. 建立小规模检索证据标注集，计算指标并整理失败样例。

项目完成的证据不是“能问出答案”，而是包含数据版本、配置、逐题结果、指标计算脚本和错误分析的可复现实验报告。
